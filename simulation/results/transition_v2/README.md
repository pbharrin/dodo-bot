# Transition v2 validation

**The transition is still unsolved.** Active unloading changed the measured foot load, but the current heel-pivot path approached thigh contact before the release conditions were satisfied.

The final standalone script was run on the unchanged v4 model with default left-support settings. A control comparison used the same script with `--disable-active-unloading`. To avoid repeating the unchanged geometric search, the development comparison harness loaded the previously computed plan; its rock and lift `qpos` arrays were verified identical to the fresh standalone plan. This is marked `development_cached_plan` in the control JSON. The distributed script always plans normally.

These are termination-state comparisons at different times, not a claim of improved transition performance. The active run began unloading at 9.002 s with about 4.435 N on the swing foot. The run stopped at the default 0.5 mm clearance threshold, before the four-second force ramp could complete. Left hip yaw and right ankle pitch were at their limits; the signed margin fields show small MuJoCo soft-limit penetrations. Motor torque was not saturated.

One local posture update was attempted and rejected: it would have moved the COM approximately 0.885 mm opposite to the requested lateral direction and increased the COM residual. That candidate was never applied. This shows why accepting a pose based only on millimeter-scale IK tolerances is insufficient for very small feedback corrections.

## Diagnostics verified

Five automated regression checks passed:

- Measured force and COM margin prevent an invalid release, even when predicted swing force is zero.
- Force feedback remains bounded without integrator windup at its lower limit.
- Posture requests mirror with the support side; failed requests freeze integration and do not reset simulated state.
- Signed collision-distance gradients agree with finite differences both outside contact and during penetration.
- The independent LP diagnostic identifies an intentionally infeasible constraint set.

Earlier development trials with the old gradient reached tiny thigh penetrations and reported QP infeasibility. A finite-difference check exposed a reversed signed-distance gradient during penetration, which is corrected in this version. Optional soft-contact trials did not establish a successful transition. The final defaults retain rigid contact constraints and stop before contact.

Validation environment: Python 3.12, MuJoCo 3.17.0, OSQP 1.1.3, NumPy 2.3.5, SciPy 1.17.0. No full right-support validation or new video-rendering validation is claimed.
