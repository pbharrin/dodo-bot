# Single-foot balance: successful baseline

The uploaded left-support run achieved `SUCCESS_BALANCE_ONLY`: ten continuous seconds meeting the measured balance thresholds, after approximately 34 ms of settling.

**Scope:** the robot is initialized in a searched one-foot pose at time zero. This result does not demonstrate transferring from two feet, push recovery, or walking. The subsequent transition experiment stalled while unloading; it is not this successful baseline.

## Files

- [Standalone experiment](../../experiments/dodo_single_support.py): pose search, static feasibility check, contact-aware inverse-dynamics QP, and measured success checks.
- [Exact tested floating model](../../models/dodo_floating.xml): generated from the existing v4 generator without geometry changes.
- [Original uploaded JSON summary](single_support_left.json): parameters, versions, pose, thresholds, and outcome.
- [Original uploaded CSV log](single_support_left.csv): measured trajectory and motor torques.

The JSON and CSV are preserved as uploaded. The CSV records selected simulation steps, not every integration step. The original summary did not record a controller hash; the accompanying controller is the retained experiment source from this session.

## Reproduce

From the repository root, with your Python virtual environment activated:

```bash
python -m pip install -r simulation/requirements.txt
python simulation/experiments/dodo_single_support.py \
  --model simulation/models/dodo_floating.xml \
  --mode balance --support left \
  --output simulation/results/local/single_support_left
```

A passing run exits with status 0 and reports `SUCCESS_BALANCE_ONLY` in the new JSON. Output goes to a separate directory to preserve the archived run.

The uploaded run used MuJoCo 3.17.0, OSQP 1.1.3, NumPy 2.5.4, and SciPy 1.18.1. Numerical details can vary across environments. To use the same MuJoCo and QP solver versions:

```bash
python -m pip install mujoco==3.17.0 osqp==1.1.3
```

For headless video on Ubuntu using CPU rendering:

```bash
sudo apt-get update
sudo apt-get install -y libosmesa6
MUJOCO_GL=osmesa PYOPENGL_PLATFORM=osmesa \
  python simulation/experiments/dodo_single_support.py \
  --model simulation/models/dodo_floating.xml \
  --mode balance --support left \
  --output simulation/results/local/single_support_left_video \
  --video simulation/results/local/single_support_left.mp4
```

The full thresholds are in the JSON. Success requires actual airborne clearance, negligible swing-foot force, a loaded and stationary support foot, COM and CoP margins, low COM speed, torque reserve, and no unwanted contacts. No external supporting force is applied.

The original 2.07 kg model has 130 mm hip-center spacing and no ankle-roll joint. Model SHA-256:

```text
221a508b97a0a16b66a7dec9a6afc3cb43232b1873c3cc5a2b6a64424ab2ccd0
```

Regenerate the XML with `python simulation/models/build_model_v4.py`; this also generates the fixed-base model. The floating model generated by the repository's existing generator was checked against the recorded hash.

The optional `--mode transfer` and push arguments are exploratory tests, not established successful capabilities. The next research milestone is a measured two-foot-to-one-foot transition using the unchanged model.
